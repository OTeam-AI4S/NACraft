# Portable AF3 presearch bundle

This bundle runs the AF3 data pipeline once for a set of unique target-protein
sequences and extracts a reusable MSA/template cache. NACraft uses the cache
during Boltz-guided design and AF3 validation, avoiding repeated sequence and
template searches for every designed aptamer.

The tracked `input/` files cover the released NA-12, protein-target and
target-selective benchmarks. Regenerate them whenever a released target
manifest changes.

## Layout

```text
presearch_bundle/
|-- input/
|   |-- presearch_input.json
|   |-- presearch_manifest.csv
|   `-- presearch_targets.fasta
|-- scripts/
|   |-- build_presearch_input.py
|   |-- run_af3_presearch.sh
|   |-- run_official_presearch.py
|   |-- extract_presearch.py
|   `-- extract_presearch.sh
|-- raw/                         generated AF3 data-pipeline output
|-- out/                         extracted portable cache
`-- README.md
```

`raw/` and `out/` are generated and should not be committed.

## Configure AF3

Run from this directory and use paths relative to the copied bundle or cluster
workspace:

```bash
cd NACraft/experiments/drylab_benchmark/presearch_bundle
export AF3_SIF="../../../../model_assets/containers/alphafold3.sif"
export AF3_MODEL_DIR="../../../../model_assets/af3_models"
export AF3_DB_DIR="../../../../model_assets/af3_databases"
export AF3_CODE_DIR="../../../../third_party/alphafold3"
export APPTAINER="apptainer"
export NUM_WORKERS=4
```

The paths above are examples; when the bundle is copied independently, place
or link `model_assets/` and `third_party/` relative to the bundle, or export
site-specific values when submitting the job.

The runner performs data-pipeline work only:

```text
--run_data_pipeline True
--run_inference False
```

Official AF3 is detected through `AF3_CODE_DIR/run_alphafold.py`; list-form
inputs are split into one JSON per target and run with bounded parallelism.
For a legacy `launch.py`, the launcher must preserve `*_data.json`, because
those files contain the MSA and template records consumed by extraction. If a
legacy launcher removes them, set `LAUNCH_PATCHED` to a compatible local
launcher.

## Run presearch

```bash
mkdir -p logs raw out
bash scripts/run_af3_presearch.sh
```

For Slurm, create a small site-specific wrapper without embedding paths in the
released script:

```bash
#!/usr/bin/env bash
#SBATCH --job-name=nacraft_presearch
#SBATCH --partition=gpu
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=32
#SBATCH --mem=128G
#SBATCH --time=24:00:00
#SBATCH --output=logs/presearch_%j.out
#SBATCH --error=logs/presearch_%j.err

set -euo pipefail
cd NACraft/experiments/drylab_benchmark/presearch_bundle
export AF3_SIF="../../../../model_assets/containers/alphafold3.sif"
export AF3_MODEL_DIR="../../../../model_assets/af3_models"
export AF3_DB_DIR="../../../../model_assets/af3_databases"
export AF3_CODE_DIR="../../../../third_party/alphafold3"
export NUM_WORKERS=4
bash scripts/run_af3_presearch.sh
```

## Extract the cache

After AF3 finishes, verify that one data JSON exists for every unique protein
entry, then extract the portable cache:

```bash
find raw -name '*_data.json' | wc -l
bash scripts/extract_presearch.sh
```

The principal output is:

```text
out/index.json
```

It is keyed by the exact protein sequence and references extracted A3M and
template CIF files below `out/`.

## Use the cache

```bash
cd ../../../..
python NACraft/main.py \
  --config NACraft/experiments/drylab_benchmark/configs/na12/de_novo/8X0N.yaml \
  --presearch-json NACraft/experiments/drylab_benchmark/presearch_bundle/out/index.json \
  --presearch-outdir NACraft/experiments/drylab_benchmark/presearch_bundle/out \
  --outpath outputs/na12/8X0N
```

AF3 validation receives the same `--presearch-json` and
`--presearch-outdir`. The cache loader rewrites stored paths relative to the
specified output directory, so the complete `out/` directory can be copied
between clusters.

Jobs that depend on presearch can be submitted in advance with a scheduler
dependency:

```bash
sbatch --dependency=afterok:<PRESEARCH_JOB_ID> downstream_design.sh
```

## Regenerate input files

```bash
python scripts/build_presearch_input.py \
  --manifest ../targets/na12/target_manifest.csv \
  --manifest ../targets/protein_antigen/targets.csv \
  --manifest ../targets/target_selective/target_manifest.csv \
  --out-dir input
```

The input tables must include target IDs and exact protein sequences. Duplicate
protein sequences, including repeated target-selective contexts, are collapsed
so each unique sequence is searched once. OGA504 uses the separate presearch
input generated by the OGA workflow.
